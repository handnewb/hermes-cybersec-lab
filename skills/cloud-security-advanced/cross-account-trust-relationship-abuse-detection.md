# Cross-Account Trust Relationship Abuse Detection

## Purpose
Cross-account trust relationships can be a security risk if not managed properly. This skill helps identify potential abuse by monitoring and analyzing cross-account relationships in your AWS Organizations hierarchy.

## Prerequisites
- Familiarity with AWS Organizations and its features
- Knowledge of AWS CloudTrail and its logging capabilities
- Experience with AWS Config and its configuration management

## Procedure

### Step 1: Create a CloudWatch Events Rule to Monitor Cross-Account ARN Changes
```bash
aws cloudtrail create-event-source-mapping --event-type cross-account-arn-change \
--prefix "arn:aws:*:"
```
This step creates an event source mapping that monitors changes to cross-account ARNs in your AWS Organizations hierarchy.

### Step 2: Create a CloudWatch Logs Group and Subscribe to Cross-Account ARN Change Events
```bash
aws cloudwatch log-group create --name cross-account-arn-change-log \
--subscription-name arn-change-subscription
```
This step creates a new log group and subscribes it to the events generated by the event source mapping created in Step 1.

### Step 3: Use AWS Config to Monitor Configuration Changes Across Accounts
```bash
aws config get-config --account-id <ACCOUNT_ID> --output json
```
This step retrieves the configuration data for a specific account and monitors changes across accounts using AWS Config.

## Expected Results
- A CloudWatch Logs group containing events related to cross-account ARN changes.
- Regular updates to your AWS Config dashboard indicating changes in resource configurations across accounts.

## Common Pitfalls
- Insufficient permissions or access to event source mappings and log groups.
- Not regularly monitoring and analyzing cross-account relationships for security breaches.
